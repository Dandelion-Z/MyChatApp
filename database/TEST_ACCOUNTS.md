## 2. 固定好友关系

- `test_alice` ↔ `test_bob`：双向好友；
- `test_alice` 与 `test_charlie`：不是好友；
- `test_david`：默认没有任何预设好友关系。

好友关系写入现有 `friendships` 双向表结构。

## 3. 两个本地数据库

| 数据库           | 用途                                       |
| ---------------- | ------------------------------------------ |
| `mychatapp`      | 本地手动测试 / 真实 Electron Renderer 联调 |
| `mychatapp_test` | 自动化测试优先使用                         |

两个数据库使用**相同的固定账号和基础好友关系**，便于手动测试与自动化测试共用账号体系。

初始化脚本只允许连接本机数据库，并会核对实际数据库名；不会连接或修改非本地数据库，也不会修改其他已有账号。

## 4. 初始化脚本

脚本位置：

```
database/scripts/seed-test-users.ts
```

执行：

```bash
npm run db:seed-test-users
```

脚本行为：

1. 读取 `server/.env` 中的 `DATABASE_URL`（必须是本地 `mychatapp`）；
2. 推导出本地 `mychatapp_test` 连接；
3. 分别在两个数据库中执行事务化初始化：
   - 不存在则创建四个固定账号；
   - 已存在则不重复创建；
   - 若固定账号的密码无法用测试密码验证，则只重置该固定账号的密码哈希；
   - 若固定账号被误软删除，则恢复该固定账号；
   - 已存在 Alice ↔ Bob 好友关系时不重复插入；
4. 不删除账号、不删除消息、不清空数据库、不修改其他用户资料；
5. 失败时按数据库回滚当前事务；
6. 不输出密码哈希、数据库密码或 JWT_SECRET。

脚本是可重复执行的：重复运行不会产生重复账号或重复好友关系。

> 前置条件：`mychatapp` 与 `mychatapp_test` 均已创建，且已执行初始迁移（存在 `users`、`friendships`、`messages` 表）。脚本会检查表结构，缺失时明确报错。

## 5. 后续测试数据管理规则

- 固定测试账号**长期保留**，不要随意删除。
- 日常开发、联调和自动化测试优先复用这四个账号。
- 不要每次测试结束后删除固定账号。
- 自动化测试优先使用 `mychatapp_test`。
- 手动 Electron 测试使用 `mychatapp`。
- 临时消息和临时测试数据可以按测试范围清理，但只能清理**本次测试创建的明确数据**。
- 不得使用宽泛 SQL 批量删除所有测试用户或所有消息。
- 不得修改或删除其他已有用户、好友关系或消息。
